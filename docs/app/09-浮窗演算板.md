# 09 · 浮窗演算板

> 源码：`app/lib/floatpad/float_pad.dart`（悬浮球 + 面板）、`app/lib/floatpad/scratch_canvas.dart`（画板）
> 内核：`lib/calc/expression.dart`（算式解析 · 精确求值 · 竖式挑选）、`lib/core/rational.dart`（有理数）
> 渲染：复用 `app/lib/render/vertical_view.dart`（竖式 / 长除法 CustomPainter）
> 入口：**不占 Tab** —— 挂在 Navigator 之上，任何页面随时可点

---

## 1. 这是个什么东西

一个**悬浮在 App 里的小演算台**：屏幕右侧靠下有一个蓝色圆形按钮，可以拖着走；
点一下展开成面板，里面左半边输算式、右半边（平板）或下边（手机）出结果和竖式，
再切一个「画板」模式就能用手指打草稿。看完点空白处或 × 收起。

它服务的是一个很具体的场景：

> 孩子在桌上写作业，家长坐在旁边。孩子问「58 除以 7 等于多少」，
> 或者要检查「3.5 加 2.25 对位没对」—— 家长不想退出当前页面、
> 也不想打开系统计算器（那个不认竖式，也不认分数）。

PC 端另有一个独立的浮窗演算器（`tool/floatcalc/`，Python + tkinter，双击
`start_float_calc.bat` 启动），**两边共用同一套口径**（精确有理数、一步算式才出竖式、
循环节重复两遍），只是载体不同：PC 版是系统级置顶窗口，手机/平板版是 App 内浮窗。

## 2. 界面结构

### 2.1 悬浮球（收起态）

| 元素 | 行为 |
|---|---|
| 蓝色圆形按钮 | 单击展开面板 |
| 拖拽 | 跟着手指/鼠标移动，松手停在原地；位置被限制在屏幕内 |
| 默认位置 | 底部导航上方、靠右 —— 不挡路，又一点就到 |

### 2.2 面板（展开态）

| 区域 | 内容 |
|---|---|
| 顶栏 | 标题「演算板」、模式切换（计算 / 画板）、× 收起 |
| 算式输入框 | 输入即算；`=`（或键盘"完成"）计入历史 |
| 结果区 | 大字结果 + 辅助行（循环节 / 分数 / 带分数） |
| 竖式区 | 一步算式自动出竖式或长除法，附分步话术 |
| 小键盘 | 7 8 9 ÷ / 4 5 6 × / 1 2 3 − / 0 . = + / ( ) 又 % |
| 历史条 | 最近 12 次「算式 = 结果」，点一下把算式填回输入框 |
| 画板模式 | 四色笔 + 橡皮 + 撤销 + 清空，白底草稿纸 |

### 2.3 平板适配

按**最短边 ≥ 600** 切宽布局：左边输入 + 小键盘，右边结果 + 竖式 + 历史，
一屏看完不滚动；手机则是窄布局（上下排，中间区域可滚动）。
主界面仍然锁竖屏（竖式和几何题横屏会被压扁，这是 A 系列早期决策），
平板竖屏下宽度也够宽布局使用。

> 实测（模拟器 `wm size 1280x1920` 强制平板分辨率）：`58÷7` 在宽布局下
> 左栏出「8.285714… + 循环节/分数/带分数」、右栏出长除法竖式与
> 「58 ÷ 7 = 8 …… 2」，截图 `app/build/shots/90-fp-p-tablet-result.png`。

## 3. 点下去发生什么

### 3.1 算一个数

输入 `58÷7`，松手即算：

| 行 | 内容 | 来自 |
|---|---|---|
| 大字 | `8.285714…` | 循环小数，循环节重复两遍后省略 |
| 辅助 | `循环节 285714` | 明确告诉家长"哪些位在循环" |
| 辅助 | `分数 58/7` | 精确值 —— 分数才是这个数的本来面目 |
| 辅助 | `带分数 8又2/7` | 小学分数题的标准写法 |
| 竖式 | 长除法"厂"形，逐步试商 | 复用 `LongDivisionView` |
| 话术 | `58 ÷ 7 = 8 …… 2` | `LongDivision.display` |

### 3.2 支持的输入写法

| 写法 | 例子 | 说明 |
|---|---|---|
| 小数 | `3.5+2.25` | 出**小数点对齐**的小数竖式（不足补 0） |
| 分数 | `1/3+1/6` | `/` 恒为除号，分数是除出来的结果 |
| 带分数 | `2又1/3` | 归一化阶段展开成 `(2+1/3)` 再算 |
| 口语 | `4分之3` | 展开成 `(3/4)` |
| 百分号 | `50%×160` | 后缀运算，也可挂括号后：`(1+2)%` |
| 全角符号 | `３＋４`、`６×７÷２` | 数字与运算符全角都能吃 |
| 千分位 | `1,234+1` | 数字间的逗号自动去掉 |
| 幂 | `2^10`、`2^-1` | 指数限整数（小学范围内够用） |
| 括号 / 隐式乘 | `(3+4)×5`、`2(3+4)` | 后者按乘法算 —— 家长算面积时常这么写 |

### 3.3 什么情况**不出**竖式

| 情况 | 行为 | 为什么 |
|---|---|---|
| 多步算式（`3+4×5`） | 只给结果 | 教材竖式只有一行运算，多步排竖式是杜撰 |
| 带括号 | 只给结果 | 同上 |
| 小数乘 / 小数除 | 只给结果 | 要先"挪小数点"再排，版面极易误导 |
| 结果为负的减法 | 只给结果 | 小学竖式不排负数 |
| 除零 | 红字「除以零」 | 不崩、不猜 |

## 4. 背后靠什么算出来

### 4.1 引擎：`lib/calc/expression.dart`

三条口径，与 PC 端 `tool/floatcalc/engine.py` **逐条对齐**（改一边必须同步改另一边）：

1. **一律精确有理数**。全程 `Rational`（BigInt 分子分母），`0.1+0.2` 精确等于 `0.3`，
   不出现 `0.30000000000000004`。家长是拿它验算孩子作业的，错一位数工具就废了。
2. **竖式只对一步算式出**。`evaluate()` 在词法层就识别「数 运算符 数」的三token
   形态并记下 `lhs/rhs/op`；多步算式走递归下降解析，不记单步信息 → 没有竖式。
3. **循环小数检测循环节，重复两遍再省略**。只写一个数字（`0.3…`）会被误读成
   "后面被截断了"；`1÷6` 的前导 `1` 不是循环节，竖排算法用余数集合天然区分。

求值器是手写**递归下降解析**（expr → term → unary → power → postfix → primary），
不用 `eval`、不引 `dart:mirrors`。错误提示说人话：「算式不完整」「括号没有闭合」
「看不懂这个字符：@」「除以零」「指数必须是整数」。

### 4.2 竖式挑选：`PadVertical.of()`

| 输入 | 产出 | 渲染 |
|---|---|---|
| 整数 +/− | `VerticalTypeset.add/sub`（含进位/退位小字） | `VerticalView` |
| 整数 × | `VerticalTypeset.mul`（逐位部分积） | `VerticalView` |
| 整数 ÷ | `VerticalTypeset.div`（逐步试商，带余数） | `LongDivisionView` |
| 小数 +/− | 自制 `decimal_±` 网格：按最大小数位列宽右对齐，不足补 0 | `VerticalView` |
| 其它 | null（不出） | — |

小数竖式是自己拼的网格（`_placeDec`）：小数部分占满末尾 `maxFrac` 列、
小数点单独占一列、整数部分向左排、最左留一列给运算符 ——
**数位对齐就是竖式的全部意义**，这是本项目从 M1 就坚持的差异点。

### 4.3 为什么不做系统级悬浮窗

| 方案 | 否决理由 |
|---|---|
| `SYSTEM_ALERT_WINDOW` 系统悬浮窗 | 要额外授权；平板分屏 / 多任务下位置和行为不可控；家长端工具不该一上来就弹权限 |
| 手写识别 | 识别错了比没有更糟 —— 家长会把识别错的数当验算结果。要手算请切「画板」模式 |

画板因此就是一块干净的电子草稿纸：四色笔、橡皮、撤销、清空，不做识别。

### 4.4 覆盖范围

浮窗挂在 `MaterialApp.builder` 的 `Stack` 里、位于 `Navigator` 之上：
五个 Tab 和 push 进来的页面（闯关、衍生题练习）都能随时点开，
且不影响各页面自身状态（`FloatPadHost` 自己管自己的展开态与拖拽位置）。

## 5. 已知边界

- **面板展开时盖住底部导航**：面板从屏幕顶端附近一直铺到屏幕底（只留 12 逻辑像素）。
  这是浮窗的常规行为（展开时本来就是"专注演算"状态），收起用 × 或点面板外的空白
  （面板几乎铺满，所以 × 是主路径，空白处只剩顶部一条）。
- **位置与历史不持久化**：拖到的位置、算过的历史只活在当次运行里，
  重启 App 回到默认位置。刻意为之 —— 浮窗是"随手"工具，不值得为它加存储。
- **长除法只接整数**：`58÷7` 可以，`5.8÷7` 不出竖式（只给结果）。
  小数除法的教材做法是先把除数变成整数，排版容易误导，宁可不画。
- **小数乘法不出竖式**，同上。
- **指数限整数且 ≤ 64**：`2^100` 拒绝（BigInt 爆炸没有意义）。
- **竖式不标小数进位的借/进位小字**：小数加减竖式只对齐、不算进位标记。
- **主界面锁竖屏**：平板横屏下浮窗宽度按竖屏设计（最短边 ≥ 600 仍走宽布局，
  但横屏时面板高度会被键盘/屏幕高度夹一次，仍可用）。
- **画板不能导出图片**：画完请截屏。要留证建议直接走错题本/导出的既有通道。
- **模拟器上 `adb shell input text` 注入的文本不触发 `onChanged`**（只进控制器、
  不实时重算），这是 adb 输入通道的老毛病，不是 App 的 bug —— 真机/真键盘输入
  每次按键都会触发。用面板小键盘或点「=」都能立即算出。
