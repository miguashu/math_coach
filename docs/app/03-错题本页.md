## 1. 这一页的核心决定：按「重要度」排，不按「错了几次」

大部分错题本的逻辑是「错一次 +1，永远累加」。这个做法有个致命问题：

> 清单会变成一面**耻辱墙**。孩子打开看到的永远是「我又欠了多少」，
> 而不是「我攻克了什么」。

所以这里的重要度是**会衰减的**：

```dart
class ImportancePolicy {
  final int wrongDelta  = 1;   // 答错 +1
  final int rightDecay  = 1;   // 答对 −1
  final int streakToClear = 3; // 连续答对 3 次 → 归零
  final int max = 10;          // 上限，防止个别考点数值爆炸
}
```

判定是否需要重点关照：`importance >= 3`。

含义是：**一道题连错 3 次会进入"重点"列表，而连续答对 3 次就彻底毕业。**
「练了很多次」和「依然不会」在这里是两件分开记的事 —— 前者交给复习间隔管，
后者交给重要度管。

## 2. 界面结构

这一页有**两段**：`错题本`（欠账清单）与`衍生题库`（补给站）。

| 段 | 一条记录代表 | 有自己的调度吗 |
|---|---|---|
| 错题本 | 一道**孩子做错过的原题** | 有（FSRS 到期 + 重要度） |
| 衍生题库 | 为某道错题**造出来的同类练习题** | 没有（只记"练过没、过没过"） |

为什么分成两段而不是混在一起：重要度统计是给家长看的决策依据
（"要重点看 3 道"），练习题混进去会把它稀释成一句没有信息量的话。

```

│  ③ 每盒有 34 支彩笔，买 7 盒…   [练过 1 次] │

└──────────────────────────────────────────┘
```

### 四格统计

| 格子 | 计算方式 |
|---|---|
| 共收录 | `_records.length` |
| 待复习 | `r.isDue(now)` 的数量 |
| 要重点看 | `r.needsAttention`（`importance >= 3`） |
| 已拿下 | `importance == 0 && rightCount > 0 && wrongCount == 0` |

「已拿下」的定义很严：必须是从没错过、且重要度已归零。
这个格子是给家长看的**正面反馈** —— 它存在，这个页面才不是一张欠账单。

### 三个筛选

| 筛选 | 条件 |
|---|---|
| 全部 | 所有记录，按重要度降序 |
| 待复习 | `r.isDue(now)` |
| 重点 | `r.needsAttention` |

### 重做前 6 题

取 `book.take(6)`（因为 `book` 已按重要度排序，即最重要的 6 道），
调用 `state.replay(list)` 放进「练习」页，然后弹提示：

> 已把最重要的 6 题放进「练习」

**注意**：这一页**不能直接作答**，是只读的。想练要回到练习页 ——
清单和练习场分开，避免在"看记录"的时候手滑改数据。

## 3. 衍生题库：判卷之后自动攒出来的练习题

### 题从哪来

练习页把卷子导成 PDF → 打印 → 孩子做完 → 「拍照判卷」拍回来。
判错的题除了进错题本，还会**自动衍生出 3 道同类题**存进这里
（生成逻辑在 `lib/ai/derive.dart`，见 `08-联网AI与实测.md`）。
错题本页这一段就是这批题的存放与练习入口。

### 「同类题」是同到哪一步

**同算法**，不只是同知识点或同名字。所以衍生题会跟原题问同一件事：
原题问**面积**就只出面积题（不会变周长）、原题是**减法**就只出减法题
（不会变加法）、原题是**两步**（倍数求和、购物找零）就只出两步题。

理由是过关判定：一条题连对两次就标"已过关"，如果衍生题把算法换了，
这个"过"就不成立 —— 孩子练会的是另一个考点。**宁可不出题，也不出错考点。**

这条是拿真机跑出来的教训（2026-10-17 模拟器实测，四类换算法的衍生题），
细节与修法见 `08-联网AI与实测.md` §6。

### 三格统计与「练未过关的」

| 格子 | 计算方式 |
|---|---|
| 衍生题 | `bank.count` |
| 未过关 | `!entry.passed` 的数量 |
| 覆盖错题 | 衍生题挂靠的**不同来源错题**数 |

「练未过关的 N 道」把当前所有未过关的题凑成一张小卷，一把练完 ——
比一组一组点开省事，家长的真实动作是"今天有空，把没过的练一下"。

### 过关判定：连对两次

```dart
static const passStreak = 2;   // BankEntry.passStreak
```

- **不是"对一次就过"**：这类题是换数字的同型题，答对一次很可能是顺着上一题
  的惯性顺出来的；
- **也不是 3 次**：练到第三遍，孩子记住的往往是数字而不是方法。
- 过关**只升不降**：连对两次已经证明会了，后来手滑一次不收回勋章
  （但 `wrongCount` 会如实 +1，状态标成"练过 N 次"）。

### 一条衍生题的三种状态

| 标 | 条件 |
|---|---|
| 没练过 | `attempts == 0` |
| 练过 N 次 | `attempts > 0 && !passed` |
| 已过关 | `passed` |

### 练完之后

`BankPracticePage` 交卷 → `state.submitBankPractice()`：

- 题库记痕迹（`attempts` / `wrongCount` / `streak` / `passed`）；
- **答错的题进错题本**，进复习队列 —— 它是孩子真做错的一道题；

> 答对的题**不进**错题本，这是和练习页不一样的地方（练习页把每次作答都记进复习库）。
> 理由是衍生题属于"补给"：做对了就是会了，再往错题本里塞只会让那张清单变长，
> 而清单变长会削弱它作为决策依据的价值。

**落账读的是「交卷那一刻的作答快照」，不是输入框**（2026-10-17 修）：

交卷后页面会重建，而共享的题目卡片会把外部 `TextEditingController` 里的内容
按 `input` 参数同步一次。原来 `input` 传 null 被当成"应该显示空串"，
于是重建时把作答清空 —— 屏幕上答案消失，落账读到的也全是空串，
**练了 3 道题库里一条痕迹都没有，界面上还看不出任何异常**
（只有把设备上的 `bank.json` 拉下来对账才发现 `savedAt` 没变）。

现在两条一起改：`input` 传 null 的语义是"别动这个框"，练习页显式传 `''`
（它确实需要"换一套题就清空"），落账用交卷时定死的快照。
界面状态是**界面**的，不能当作"孩子写了什么"的事实来源。

### 移除

整组的来源题干下方有「移除这一组」→ 弹确认框 → `bank.removeBySource(id)`，
一次删掉这道错题衍生的全部练习题。**错题本里的原题不受影响**；
反过来，从错题本移除原题**也不会**连带删掉衍生题（练习题本身还是好题，
页面上会标一句"原题已移出错题本"）。

## 4. 变体闯关：一道错题换数字再练

错题本每条记录右下角有个蓝色拼图图标 → 「变体闯关」。
它和「衍生题库」是两件事：**闯关是家长主动点的、当场就能练的一组题**；
衍生题库是判卷后自动攒下来慢慢练的。

### 四层映射：先问"这道题是什么算法"，再问"题型叫什么"

家长 2026-10-17 的原话是「错题本变体闯关都是固定的分数相加减」。
查下来是两个病根叠在一起：

1. 兜底函数 `fallbackVariantKind(5)` **写死**返回 `fracAddSub` ——
   五年级不管点什么题，只要前两层没匹配上，出的就是分数加减；
2. 23 个题型里**一半根本没有映射**，于是大量点击都掉到了那个写死的兜底上。

现在的优先级是四层，逐层往下，**判不出就停，不许猜**：

| 层 | 函数 | 判什么 | 判不出怎么办 |
|---|---|---|---|
| ① | `localRecipeFor` | 题干 → `VariantShape` **算法结构**（`rect` 分清面积/周长、`timesAs` 分清一步/两步、`shopping` 是找零两步） | 落到 ② |
| ② | `variantKindFor` | 宽松·只看题型名 | 落到 ③ |
| ③ | `variantRecipeByStem` | **按题干文字推断算法**：裸算式 → 四则运算；含"周长"→`rectPerim`；含"面积"+三角形 →`triArea`；含"倍"→`timesOneStep` 或 `mulThenAdd`；含"找回/付给/售货员"→`mulThenSub`；带余数除法→`divRem`；两个单位词→`unitConv` | **返回 null**，落到 ④ |
| ④ | `fallbackVariantKind(grade, salt:)` | 按年级**轮换**（五年级在分数加减、两位数乘法、长方形面积周长、三角形面积、有余数除法之间转） | 无 |

第 ③ 层刻意设了一批 **bail-out**（直接认输交给 AI）：梯形、平行四边形、组合图形、
格点、立体图形/展开图、圆柱、长方体、正方体、圆锥、混合运算、植树、间隔、
平均数、"几分之几" —— 这些要么本地模板不足，要么判错结构比不出更糟。
判错结构就是 A17 说的"答案对但练错考点"，比不出题更糟。

### 异步生成：本地没有同算法模板的，当场问模型

匹配不上的源题不是被丢掉，而是进一条 `_pending` 队列，由 `VariantAgent` 在后台生成
（带本地复算与五道闸门，与衍生题库同一套标准），生成完再插回列表。
所以点开「变体闯关」通常是**先看到本地毫秒级出的题，AI 那几道稍后补上**。

AI 那一路整体失败（没配 key、网络断、全被闸门拦）时，才降级成按年级轮换的常规题，
并且**在卡片上明写「同年级常规练习」** —— 家长能看出这不是按这道错题量身定出的。
每一次点「再来一组」都会让轮换的 `salt` 前进一位，不会连着两轮拿到同一套。

### 界面上的三种标签

| 标签 | 含义 |
|---|---|
| `同类变体` | 走了 ①②③ 层，算法结构与原题一致 |
| `同年级常规练习` | 走了 ④ 层兜底，**算法结构没有保证** |
| `AI 生成` | 走模型那一路，过了本地复算 |

## 5. 卡片上的信息

每张卡片右上角有角色标：

| 角标 | 条件 | 颜色 |
|---|---|---|
| `重要度 N` | 总是显示 | ≥4 红 / 1–3 橙 / 0 绿 |
| `错 N 次` | `wrongCount > 0` | 灰 |

卡片内容来自 `RecordCard`：把 `ReviewRecord` 转成 `QuizQuestion` 后复用
`QuestionCard`，但 `readonly: true` —— **不显示输入框，直接显示正确答案。**

## 6. 移除记录

点右下角垃圾桶 → 弹确认框：

> **从错题本移除？**
> （题干前 40 字…）
> [取消] [移除]

确认后 `state.forget(id)` → `repo.delete(id)` + `save()`。

**题干为什么要截断到 40 字**：数学题题干经常很长（尤其是应用题），
直接塞进对话框会撑破布局。

## 7. 已知边界

| 边界 | 说明 |
|---|---|
| 只读 | 不能在错题本里作答，只能「重做前 6 题」送回练习页 |
| 「重做前 6 题」固定 6 道 | 不可配置 |
| 移除不可撤销 | 删了就是删了，没有回收站 |
| 不显示历史作答记录 | 只有累计的 `wrongCount` / `rightCount`，看不到某次答了什么 |
| 无搜索 / 无按年级筛选 | 记录多了只能滚动找 |
| 排序只有重要度一种 | 不能按时间、按年级排 |
| 衍生题不参与 FSRS 调度 | 它不排到期时间，只排"过关没"；复习调度仍由错题本里的原题负责 |
| 衍生题不进备份 | 「导出备份」只含错题本；题库可由错题重新衍生（判卷时会自动补） |
| 题库上限没做清理 | 练过的题会一直留着。要清就「移除这一组」；没有一键清空（避免误删） |
