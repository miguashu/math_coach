# 01 · 练习页

> 源码：`app/lib/pages/practice_page.dart`
> 底部导航第 1 个 Tab

---

## 1. 这一页解决什么问题

「今天练什么」这件事，对家长来说通常有两种做法：

- **翻练习册找题** —— 找得到题，但不知道孩子哪块不会，练完也不知道记没记住。
- **让孩子自己刷 App** —— 题目随机，跟学校进度对不上，错题也没人管。

这一页走的是第三条路：**按年级和知识点精确选题，一次出一套，做完当场批改，
错的自动进错题本，明天自动再出现。** 选题权在家长手上，记忆归应用在管。

## 2. 界面结构

```
┌────────────────────────────────┐
│  练习                  三年级 ▾ │  ← 蓝色头部（三行约 120px）
│  [基础][提高][奥数挑战]    [PDF]│  ← 难度 chips + 导出图标
│  [全部知识点 ▾][题数 6 ▾][换一套]│  ← 选择器 + 出题按钮（同一行）
│  ⓘ 本套含 3 道 AI 新题…         │  ← 出题结果说明（可没有）
├────────────────────────────────┤
│  ┌──────────────────────────┐  │
│  │ 第 1 题   数与代数 / … AI │  │
│  │                          │  │
│  │ 用竖式算一算：47 + 38 =   │  │
│  │      [ 竖式图 ]          │  │
│  │ ┌────────────────────┐   │  │
│  │ │ 在这里作答          │   │  │
│  │ └────────────────────┘   │  │
│  └──────────────────────────┘  │
│            … 第 2..N 题 …       │  ← 可滚动（占主体空间）
├────────────────────────────────┤
│  [ 📷 拍照判卷 ] [ ✓ 提交批改 ] │  ← 底部条（有题时才出现）
└────────────────────────────────┘
```

> **2026-10-16 重做**（家长原话："这个布局不合理"）：旧版头部占了近半屏 ——
> 年级两行 chips + 难度 chips + 两个下拉 + 大全宽按钮 + PDF 按钮，
> 题卡被挤成一条，键盘一弹连题都看不见。新版头部压到三行，
> 年级/知识点/题数改走底部弹层（比内嵌下拉省一行高度，选项也看得清），
> 出题按钮缩成工具栏里的实心小按钮。作答点中题卡时，
> 卡片会自动滚进键盘上方的可见区（见 `onAnswerFocused`）。

### 顶部操作区

| 控件 | 行为 |
|---|---|
| 年级 | 胶囊按钮，点开底部弹层选 1~6 年级，默认**三年级**。切换年级时**清空已选知识点**（不同年级的单元名不一样） |
| 难度 | 三档 chips：**基础**（纯本地模板，不联网）/ **提高**（一半 AI 新题）/ **奥数挑战**（AI 为主，本地兜底） |
| 知识点 | 弹层列表来自 `KnowledgeIndex.unitsByGrade(grade)`，即人教版该年级的单元名；「全部知识点」= 不限 |
| 题数 | 弹层选 4 / 6 / 8 / 10，默认 6 |
| PDF 图标 | 把当前这套题导出成可分享打印的 PDF（有题时才出现） |
| 换一套 | 工具栏实心小按钮；AI 出题期间转圈显示「出题中」，此时本地题已经在屏幕上 |

> **难度档为什么这么分**：本地题库是模板式的，一套参数翻来覆去就那几种形态，
> 而且只覆盖教材一部分单元（五年级 11 个单元里 6 个没有模板）。
> 「基础」档刻意不联网 —— 离线也要能出题，且基础题本地模板更稳；
> 「提高」「奥数挑战」才让模型出场出应用题，答案过了本地验算才上卷。

### 空状态

还没出题时，中间是提示文案：

> 还没有题目
> 上面选好年级和难度，点"出一套题"。
> 「基础」档在本地出题，不联网；「提高」「奥数挑战」由 AI 现场出应用题，
> 答案经本地验算后才上卷。

「基础档不联网」这个承诺仍然有效，而且现在是显式的：选基础档，
整个出题流程一次网络请求都没有。

## 3. 点下去发生什么

### 出一套题

```dart
Future<void> _newPaper() async {
  for (final c in _ctl.values) c.clear();   // 先清掉上一轮的作答
  await widget.state.newPractice(
      grade: grade, count: count, unit: unit, level: level);
}
```

`newPractice`（`app/lib/state.dart`）分两步走，**本地题永远先上屏**：

1. **本地立即可出**：`QuizGenerator.generateMany` 按老规矩抽题
   （题型工厂筛年级 → 筛知识点 → 过正确性闸门 → 去重）。
   这一步不联网，点下去几十毫秒内卷子就出来了，绝不空屏。
2. **AI 增量混入**（仅「提高」「奥数挑战」档）：
   - 要几道：提高档取一半、奥数档取整卷（上限 6 道）；
     所选知识点本地题库没覆盖时（如五年级「图形的运动（三）」），
     提高/奥数档**整套交给 AI**；
   - `QuizAgent.generate` 按每次 ≤3 道分批问模型，答案用本地 `Rational`
     从 equation 复算，对不上整道丢弃，不合格打回重做一次；
   - 混卷规则：AI 题在前，本地题补足，题干归一化去重，**绝不为空**；
   - 出完在按钮下方给一行说明（如「本套含 3 道 AI 新题（答案已本地验算）」）。

AI 出题期间按钮转圈显示「AI 出题中…」，此时本地题已经在屏幕上，
孩子可以先做起 已有的题 —— 不是黑屏等模型。

> **为什么不默认 AI 出题**：基础档一次网络请求都没有，这是 App 的核心承诺。
> 而且模型出题有 30 秒量级的延迟和失败率，本地题库才是"随时能练"的那条路。

### 提交批改

```dart
onPressed: () async {
  FocusManager.instance.primaryFocus?.unfocus();  // 先收键盘
  await state.submit();
}
```

`submit()` 对每道题：

1. 取输入，`trim()` 后判空 —— **留空算错**（不做"未答不判"的特殊处理，因为练习场景就是要给反馈）；
2. `QuizAnswer.check(input)` 精确比对；
3. `repo.recordAttempt(...)` 写入错题本、更新 FSRS 与重要度；
4. 落盘 `wrongbook.json`。

批改之后：

- 卡片**边框变色**（对绿 / 错红），右上角出现勾选或叉号图标；
- 输入框**禁用**（防止改答案自欺）；
- 卡片底部展开**讲解区**：
  - 答对 → 绿色「思路回顾」，列出分步讲解；
  - 答错 → 红色「这题再看一遍」，先给正确答案，再列分步讲解；
- 底部条变成「答对 X / N」+ 副文案：
  - 全对 → 「全对，这一轮可以过了」
  - 有错 → 「错的已经进错题本，明天会再见到」

> **讲解为什么只在提交后出现**：答案讲得太早等于没练。
> 这条写在 `practice_page.dart` 的类注释里，是这一页的产品原则，不是实现细节。

### 再练一套

提交后底部主按钮变成「再练一套」，点了直接换一套新题（沿用当前年级/知识点/题数设置）。

### 拍照判卷（纸上作答的路）

屏上打字不是唯一的作答方式。把这一套题**导出 PDF 打印出来给孩子做**，
写完拍一张照片，走底部条左侧的「拍照判卷」：

```
拍照/选图 → AI 认字（认出手写答案，认不出就注明）
        → 本地判分（QuizAnswer.check，逐字实时）
        → 用户可改识别结果（改完本地重判）
        → 确认批改（AI 给答错的题写批语 → 错题进错题本）
        → 【后台】每道错题衍生 3 道同类题 → 进「错题本 → 衍生题库」
        → 回到练习页看讲解
```

**分工是这个功能的生死线**（详见 `docs/app/08` 与 `lib/ai/grader.dart`）：

- 模型只**认字**：手写答案原样抄出，认不出留空 + 注明，不许猜；
- **对错永远由本地判分规则定**：模型把 `79` 认成 `96`，本地判分直接逮住；
  全角、单位、小数尾零、余数写法（`7……5` 不被抹成 `7.5`）都走本地规范化；
- 模型只给答错的题**写批语**（一两句，点错因、不提正确答案）；
- **认不出不判错**：标「未识别」，琥珀色卡片，不进错题本 —— 没看清就判错是冤枉孩子。

判卷结果落账后，练习页的表现和手写提交一致：卡片变色、勾/叉、
讲解区展开、错的进错题本；未识别的题显示琥珀色「未识别」卡，
家长可以照着照片在输入框补判。

**判完卷还会自动造衍生题**：每道判错的题生成 3 道同类题，进「衍生题库」
（错题本页的第二段）。这件事在**后台跑**，判卷结果不等它 ——
本地模板毫秒级，要问模型的那类题十几秒，所以判卷页上有一条状态条
单独显示进度（"错题 2 道 → 衍生题 6 道已进题库（其中 3 道由 AI 现场出）"）。
未识别的题不衍生题：连孩子写了什么都没看清，就断言他不会、追着练，
那是拿错误的前提做训练。

> **典型场景**：家长点「PDF」→ 分享到微信/打印 → 孩子纸笔作答 →
> 家长拍照判卷 → 错的题明天自动出现在复习队列，同时攒下一批同类练习题
> 在「衍生题库」里等着练。

## 4. 各年级能出什么题

23 个题型工厂，按年级分布：

| 年级 | 可选题型数 | 题型 |
|---|---|---|
| 一 | 3 | 进位加、退位减、购物应用题 |
| 二 | 7 | 进位加、退位减、两位数×一位数、有余数除法、混合运算、单位换算、购物应用题 |
| 三 | 12 | 上表 + 两位数×两位数、长方形面积周长、格点图形、平均数、倍数应用题、间隔问题 |
| 四 | 10 | 两位数×一位数/两位数、有余数除法、混合运算、单位换算、长方形、格点图形、平均数、倍数、间隔 |
| 五 | 9 | 三角形、平行四边形、梯形、组合图形、格点、正方体展开图、长方体体积/表面积、间隔、分数 |
| 六 | 12 | 三角形、平行四边形、梯形、圆面积、圆周长、组合图形、格点、正方体展开图、长方体体积、圆柱体积、间隔、分数 |

**说明**：一年级题型少（3 个）是刻意的 —— 一年级以口算和认识数为主，
笔算竖式的考点集中在二三年级，所以题型池集中在那边。

**本地题库覆盖不到的单元**（五年级为例）：小数乘法、小数除法、位置、可能性、
简易方程、因数与倍数、观察物体、图形的运动（三）、分数的加法和减法、
折线统计图、找次品 —— 这些单元选「提高」或「奥数挑战」时整套由 AI 出题，
选「基础」会明确提示"本地题库还没收录"，而不是静默出一道别的单元的题。

**高年级池子不放低年级复习题**：长方形面积（三下）、三位数乘两位数（四上）
这类题型只注册到四年级。家长原话是"五年级的题出现一年级的简单问题"——
哪怕标签是诚实的，看到"三下"开头的题挂在五年级卷子上也扎眼。
想练回低年级内容，去低年级卷子练，或由 AI 按当前年级的情境重出。

## 5. 实现要点与踩过的坑

### ① 输入框的 controller 提到页面层持有

```dart
final Map<String, TextEditingController> _ctl = {};
TextEditingController _ctlOf(String id) =>
    _ctl.putIfAbsent(id, () => TextEditingController());
```

**原因**：如果 controller 建在 `QuestionCard` 内部，手机弹出键盘会触发重建，
`TextField` 里已经输入的字就丢了。这个 bug 在模拟器上用 ADB 输入时才暴露 ——
手动点击输入很难注意到。

### ② 换题时手动清空 controller

`_newPaper()` 里显式 `c.clear()`。因为 `_ctl` 是 `putIfAbsent` 缓存的，
换一套题后题目 id 变了，旧的输入内容会跟着 controller 留下来。

### ③ 提交前先收键盘

`FocusManager.instance.primaryFocus?.unfocus()`。
否则键盘盖住讲解区，用户提交后看不到反馈。

### ④ 出题失败不会白屏

`generateMany` 内部有兜底：如果 60 次都抽不出合法题，返回 `FCalc.add()` 的结果。
绝对不返回空列表 —— 空列表在 UI 上等于白屏，用户会以为 App 坏了。

### ⑤ 五年级冒出"一年级题"？是知识点标签错了，不是题出错了

2026-10-16 家长反馈：选五年级，第 1 题标签是「一上 · 认识图形 · 长方形」。
查下来题本身没错（长方形面积，五年级该练），错在**标签落位**：
`KnowledgeIndex.match` 原来写成"考点名唯一命中就直接返回"，而「长方形」
整个知识点表里只有一个同名考点（一年级"认识图形·长方形"），
于是不管选哪个年级都返回它。

修法：匹配顺序改成**年级优先** ——
同年级精确名 → 同年级模糊名 → 年级差最小的候选。
（"三角形的面积"同理：六年级不再掉进一年级"认识图形·三角形"。）

### ⑥ 长方体的图永远画成 5/3/2

同一个反馈里另一条：题面写"长 5 厘米，宽 3 厘米，高 6 厘米"，
图上标的却是 3 cm / 5 cm / 2 cm。原因是出题器传参数用键名 `a/b/c`，
画图求解器读的是 `w/h/d`，三个键全部落空，图形按默认值画。
已改成传 `w/h/d`，求解器同时兼容旧键名（错题本里存着老 spec，重放不能花）。

### ⑦ AI 出题为什么要分批、给 8000 token

`deepseek-v4-flash` 是推理模型：先输出思维链再输出正文。
实测一次要 4 道奥数题，思维链烧掉 4000 token 预算、正文一个字符都没出来
（`finish=length`）；给到 8000 才稳定出完。所以出题按每次 ≤3 道拆分：
一批失败只损失一批，也不会把单次调用逼到超时。
（"上限不是预扣" —— 用不到不花钱，这条在 `llm.dart` 里也写着。）

## 6. 已知边界

| 边界 | 说明 |
|---|---|
| 判分统一按文本比对 | `QuizAnswer.check` 会容忍 "0.5"/".5"/"0.50"，但**单位写错目前算对**（容差逻辑只比数值） |
| 拍照判卷认不出 ≠ 判错 | 字迹不清或空白的题标「未识别」，不记错题本；想判得对着照片手动补 |
| 拍照判卷认竖式很勉强 | 竖式答案的位置和形态太随性，模型经常认不出 —— 这种情况请手动输入，或直接用「提交批改」 |
| 拍照判卷按题号对应 | 照片里的题必须和当前这套题**顺序一致**；拍的别的卷子认出来也会按题号硬套，确认前请核对题干摘要 |
| 一次一套 | 不支持"只重做第 3 题"；想重做请去错题本用「重做前 6 题」 |
| 换年级会清空知识点选择 | 这是有意的，不同年级单元名不同 |
| 卷子不保存 | 退出 App 后当前卷子丢失（但错题记录已归档，不会丢） |
| AI 档需要联网 + 配了 key | 「提高」「奥数挑战」档和「拍照判卷」都要联网；没配 key 时自动退回本地题库并说明原因 |
| AI 题不带配图 | 闸门明确拒绝"如图/下表"类题干（本地画不出模型心里那张图）；要练几何图形请用基础档 |
| AI 出题有几十秒延迟 | 奥数档 6 道约 40~60 秒（分 2 批问模型）；等待期间本地题已经在屏幕上，可以先做 |
| AI 题的答案正确性 | 已本地验算（equation 用 `Rational` 复算，与模型自报答案一致才收），但**题目情境是否超纲**靠 prompt 约束 + 难度自评夹紧，家长仍应过目 |
| 衍生题需要题型有模板或模型给得出验算式 | 立体图形/展开图这类本地没模板的题，要联网让模型出；模型写不出一条四则式的应用题（如"够不够"）会被闸门丢掉 —— 少几道是正常的，界面会说明 |
| 判卷时衍生题有配额 | 一次批改最多为 6 道错题问模型（本地模板那一路不限额） |
