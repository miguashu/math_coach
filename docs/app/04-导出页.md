# 04 · 导出页

> 源码：`app/lib/pages/settings_page.dart`
> 底部导航第 4 个 Tab（标签「导出」）

---

## 1. 这一页解决什么问题

错题本存在手机里，孩子看屏幕做题有个很大的问题：**在屏幕上没法写草稿**。

数学不是选择题。竖式要一位一位对齐着算，几何题要在图上画辅助线，
这些动作在玻璃屏上做不了，用手指划两下也不算"练"。

所以这一页做的是把错题变成**能打印出来的 A4 练习卷**。
打印出来之后，孩子可以在纸上真正地算一遍。

## 3. 两种卷子

| 卷子 | 数据来源 | 排序 | 用途 |
|---|---|---|---|
| **错题练习卷** | `state.book`（全部记录） | `Paper.sortForPrint`：重要度降序 → 错误次数降序 | 阶段性总复习，打印一份集中练 |
| **今日复习卷** | `state.dueQueue()`（已到期） | 同左 | 当天的家庭作业 |

两个按钮的启用条件：有对应数据 **且** 中文字体已加载。

### 排序逻辑

```dart
static List<PaperItem> sortForPrint(List<PaperItem> items) {
  final list = [...items];
  list.sort((a, b) {
    final c = b.importance.compareTo(a.importance);        // 重要度高的在前
    return c != 0 ? c : b.wrongCount.compareTo(a.wrongCount); // 其次错得多的在前
  });
  return list;
}
```

**题号重新编号**：排序后题号按打印顺序重新编 1..N。
不这么做的话，按重要度排序后学生会拿到一张从「第 9 题」开始的卷子。

## 4. 导出流程

```
点「错题练习卷」
   ↓
① 校验字体是否已加载（未加载 → Toast 提示并中止）
   ↓
② 收键盘
   ↓
③ state.exportPaper(title, records, fontData)
     ├─ 把每条 ReviewRecord 转成 PaperItem
     ├─ figureSpec → FigureSolver.solve()  ← 按 PDF 精度重新求解
     ├─ verticalKind/Args → VerticalTypeset  ← 按 PDF 排版器重画
     └─ PaperPdfExporter.export(paper) → Uint8List
   ↓
④ 写到 <数据目录>/<标题>.pdf
   ↓
⑤ 弹出底部结果面板
```

### 关键点：图形是重新算的，不是截图

```dart
figure: VerticalReplay.figure(r.figureSpec),   // 拿到原始 spec
...
final figureRenderer = FigurePdfRenderer(font: gFont, fontBold: gFontBold);
```

PDF 里的几何图走的是 `FigurePdfRenderer`，和手机屏幕上的 `FigureView`
用的是**同一份 `FigureScene`**，但各自重新布局：

- 屏幕上：按 `MediaQuery` 宽度缩放，字号 11px 左右；
- PDF 里：按 A4 版心宽度排版，矢量路径输出。

所以打印出来的图形和屏幕上一样准，**不会因为放大而变糊**。

### 字体

PDF 里内嵌了 **SimHei（黑体）**，随文档打包，约 9.5 MB。
这是 APK 体积的第二个大头（第一个是引擎）。

为什么要内嵌：PDF 阅读器和打印机通常没有中文字体，不内嵌的话汉字会变成空白或方块。

```dart
final wFont = pw.Font.ttf(fontData);      // widgets 层排版用
final gFont = PdfTtfFont(pdfDoc, fontData); // 绘图层用
```

同一份字节构建两种字体对象，保证排版测量和图形绘制用同一套度量。

### 页面规格

| 项目 | 值 |
|---|---|
| 纸张 | A4 |
| 页边距 | 36 pt（约 12.7 mm） |
| 每页题数 | 4 |
| 答题空间 | 70 pt（约 25 mm） |
| 页脚 | 页码 |
| 元数据 | 标题 / 作者；**不写位置与 EXIF 信息** |

最后一条是隐私考虑：孩子的作业信息不应该随着试卷文件流出。

## 5. 导出后的结果面板

```
┌────────────────────────────────┐
│  ✓ 已生成 错题练习卷            │
│                                │
│  共 24 题。图形是按打印精度重新   │
│  求解绘制的矢量图，直接打印很清楚。│
│                                │
│  /storage/emulated/0/Android/… │
│                                │
│  [  📤 发给微信 / 打印机  ]      │
└────────────────────────────────┘
```

「发给微信 / 打印机」通过 `MethodChannel('mathcoach/storage')` 的 `share` 方法，
在 `MainActivity` 里用 **FileProvider** 把 PDF 转成 `content://` Uri，
再唤起系统分享面板（chooser）。

> **为什么必须用 FileProvider**：Android 7.0 起，把 `file://` Uri 传给别的应用
> 会直接抛 `FileUriExposedException`，而且这个异常抛在系统侧，
> 从 App 自己的日志里看不出根因。所以走 FileProvider + 临时读权限授权。

## 6. 数据区

**数据位置**：显示当前数据目录，通常形如

```
/storage/emulated/0/Android/data/com.mathcoach.app/files/math_coach
```

这是 App 的**外部专属目录**，手机自带的「文件」App 能直接找到，
导出的 PDF 可以拷出来、发微信、连打印机。
拿不到外部存储时自动退回内部目录。

**清空学习记录**：弹二次确认，文案里明确告知后果并建议先导出：

> **清空全部学习记录？**
> 错题本、重要度、复习进度都会被删除，删了就找不回来了。
> 建议先导出一份练习卷留底。
> [取消] [确认清空]

## 7. 已知边界

| 边界 | 说明 |
|---|---|
| 只有两种卷子 | 不能自定义题数、不能只选某个知识点、不能指定年级 |
| 字体固定 SimHei | 不可换；若资源加载失败，导出按钮会**变灰并显示原因** |
| 导出到 App 专属目录 | **卸载 App 会一起删掉**，请及时拷出或分享 |
| 分享依赖系统面板 | 目标应用需支持接收 `application/pdf` |
| 答题空间固定 70pt | 不随题目类型变化（应用题可能需要更多空间） |
| 无答案页 | 只出题目卷，不带答案页/解析页开关 |
