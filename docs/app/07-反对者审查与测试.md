## 一、审查清单与结论

| # | 反对意见 | 结论 | 处理 |
|---|---|---|---|
| 1 | 模型没给验算式、只有答案时，界面却亮「已本地验算」绿勾 | **确认缺陷** | 验算改三态（exact / unverifiable / mismatch）；没验算就是没验算 |
| 2 | 要求「步骤必须全面」，但模型只给一步也照单全收 | **确认缺陷** | `_isComplete`：至少 2 步 + 有答案 + 答案含数字；不完整体打回重做 |
| 3 | 同类题只是陈列题干+答案，孩子练不了、错了不进错题本 | **确认缺陷** | 新增 `adopt.dart` 把生成的题转成 `QuizQuestion`，可作答、可归档、进复习队列 |
| 4 | 「自定义」供应商没有 baseUrl 输入框，选了也没法填 | **确认缺陷** | 设置页加 baseUrl / 识别 baseUrl 两个输入框，预设只负责"帮你填好" |
| 5 | 测试连接只测文字模型，识别那一路配错也要等拍照才发现 | **确认缺陷** | 一次测两个模型，识别没配会明确提示「拍照识题不可用」 |
| 6 | 没相机 / 用户取消时点了完全没反应 | **确认缺陷** | 拍照/选图拿不到文件时给出明确提示，并引导「试试从相册选」 |
| 7 | 管理员只有接口日志，看不到孩子练得怎么样 | **确认缺陷** | 管理页加学习侧统计（错题本/今日到期/答对数/正确率）+ CSV 导出 |
| 8 | 模型答案错了怎么办？有没有兜底 | **已有，但不够明显** | 验算不符打回重做一次，仍不符亮红牌「验算不一致」；同类题答案不符直接丢弃 |
| 9 | 生成的题会不会出负数、循环小数 | **已覆盖** | 本地出题减法保证非负、除法只出有限小数；用例已断言 |
| 10 | 照片会无限堆积 | **确认缺陷** | 只保留最近 20 张 |
| 11 | 模型乱答（不按 JSON）会不会崩 | **已有兜底** | 整段话兜底成一步并标"不完整"，用例已断言不抛异常 |
| 12 | DeepSeek 能不能做拍照识别 | **取决于供应商** | 官方 DeepSeek 没有视觉模型，故设计成解题/识别**可配两家**（各有 key）；后来拿到 agicto 中转站的 key 实测，`deepseek-v4-flash` 在那里**能收图片且 OCR 全对**，于是默认改成"一家搞定"，识别地址留空即复用解题地址。仍保留可拆两家的能力 |
| 13 | 衍生题说好是"同类题"，会不会只是**名字像**、算法根本不同 | **确认缺陷（真机发现）** | 只按题型名映射 → 面积错题衍生出周长题、减法错题衍生出加法题、两步题衍生出一步题、"求几分之几"衍生出分数加减。修法：处方带 `VariantShape`，模板照结构出，判不出结构就交给模型；见 `08-联网AI与实测.md` §6 与 `test/derive_shape_manual.dart` |
| 14 | 练完衍生题，题库里真的记上了吗 | **确认缺陷（真机发现）** | 交卷后 `setState` 重建，`QuestionCard` 把外部 controller 里的作答**清空**了（`input` 传 null 被当成空串去同步），于是落账读到的全是空串 → 练 3 道一条痕迹没有，界面上完全看不出异常。修法：`input` 传 null 表示"别动这个框"，落账改用**交卷快照**；练习页显式传 `''` 以保留"换一套要清空输入"的语义 |
| 15 | 一次判卷错题很多时，模型那条路会不会把时间拖长 | **已有兜底** | 只把**没有本地模板**的错题攒成**一次**请求批量问（最多 6 道），有模板的毫秒级本地出；衍生整体 `unawaited` 出去，不挡判卷结果 |
| 16 | 拍照识题又慢、又只认一道题 —— 一张卷子上 6 道题要拍 6 次 | **确认缺陷** | 慢的根子是**上传体积**：1024px 照片 PNG 要 1935 KB，同样内容 JPEG q72 只要 265 KB（**7.3 倍**）。改由 Android 宿主编码 JPEG（`dart:ui` 只能编 PNG），只认一道题是 OCR prompt 只要求返回"这一张"——改成要求返回**整张图的所有题**（≤8），界面按题分卡，每题各自讲解/出同类题 |
| 17 | 切个 tab 再回来，拍照页白屏、练习页年级从五年级变回三年级 | **确认缺陷** | 每次 `setState` 都把整个 `body` 重建，离屏页面被 unmount、State 被 dispose。改成 `IndexedStack` + 页面只在 `initState` 建一次；光"把页面缓存成字段"不够——直接 `pages[_index]` 会摘掉离屏节点，一样丢状态 |
| 18 | 点了「出题」，秒出 6 道，可既不是 AI 出的、也不是这个单元的 | **确认缺陷** | 本地题库没收录这个单元时，原逻辑拿同年级**不相干**的题充数，还显示成"AI 已就绪"。改成：`wantAi>0` 且本地没覆盖时**先不出**，明确写「本地题库还没收录，正在用 AI 按这个单元出题」；AI 失败也只在带一句「不是「$unit」的题」的前提下回落本地 |
| 19 | 错题本「变体闯关」翻来覆去都是分数加减 | **确认缺陷** | 根因是兜底 `fallbackVariantKind(5)` 写死成 `fracAddSub`，且 23 个题型里一半没有映射。改成四层优先级：严格同算法处方 → 题型名映射 → **按题干推断算法**（面积/周长/倍/找零/余数，判不出就返回 null 不猜）→ 兜底按年级轮换；本地没有同算法模板的一律走 AI 异步生成，全部失败才用轮换兜底并明写「同年级常规练习」 |
| 20 | 速度还能不能再提 | **部分解决** | 大头是上传体积（见 16，7.3 倍）；多题 OCR 的 `maxTokens` 从 2000 放到 3000 免得思维链吃光预算。剩下的瓶颈在模型侧延迟与截图后的网络往返，内核侧已无 100ms 级以上的空转 |
| 21 | PDF 导出藏得太深，用户根本找不到 | **确认缺陷** | 原来只有设置页一个入口。改成错题本页头部一个**整行白底按钮**「导出 PDF · N 道错题（可打印）」、练习页工具栏同样式按钮，弹层抽成共享的 `export_sheet.dart`（三处共用同一份字体加载逻辑） |

## 二、测试用例（`test/ai_manual.dart`，64 条）

> 数字随每轮修复增长，以脚本实际输出为准（当前 64 条全过）。

**验算器（16 条）**：括号与优先级、全角 ×÷、小数、汉字/括号不匹配/除零返回 null、浮点容差、
**带等号的验算式**（`237+158=395` 取左边、`1+1=3` 判自相矛盾、多等号不猜、全角 `－＝＋`）

**讲解 Agent（11 条，用注入的假模型，不联网）**

| 用例 | 期望 |
|---|---|
| 正常：两步 + 算式一致 | `exact`，只调一次模型 |
| 只讲一步 | 打回重做，第二次讲完整；提示里带「至少要 2 步」 |
| 答案与自己的算式矛盾 | 打回重做，提示里带上矛盾点，第二次改对 |
| 两次都对不上 | `mismatch` 亮红牌，**不冒充正确** |
| 没给验算式 | `unverifiable`（**不是** exact）—— 第 1 条缺陷的回归 |
| 模型不按 JSON 回 | 兜底成一步、标记不完整、不抛异常 |
| 模型报错 | 异常上抛给 UI 提示，不静默 |

**拍照识别（13 条）**：取出题干与补充说明、模型不守 JSON 时兜底出文本、
正常情况用主模型、**主模型报"模型不支持"时自动换备用模型**、没配备胎时照常报错不静默吞掉；
**多题识别**（第 16 条缺陷的回归）：一次返回 N 道题按顺序取出、题干保持原有顺序、
`stem` 属性仍取第一道（老调用方不破）、`notes` 缺失时合并、只有一道题时的新老格式都认、
裸文本兜底、`items` 为空时 `stem` 返回空串

**同类题（6 条）**：本地出题答案正确（用验算器反算）、应用题交给模型、
除法不出循环小数、模型出的题答案与算式不符**被丢弃**、来源标注 local/agent

**配置（8 条）**：自定义 baseUrl 能存住、就绪判断、识别 key 留空复用主 key、
识别地址留空时复用解题地址、备用模型能持久化、默认配置开箱即用

**运行记录（5 条）**：统计（总数/失败/平均耗时）、按类型筛选、持久化后读回、清空

## 三、仍然存在的边界（如实列出）

- ~~**真实模型效果未经实测**~~ → **已补上**（2026-10-16）：拿到真实 key 后跑了
  `test/live_agicto.dart`，讲解 / 识图 / 出题三条链路全部真实联网通过，
  详见 `08-联网AI与实测.md`。那次实测又挖出两个缺陷，已修：
  1. **验算式带等号被误判非法** → 每题白白打回重做一次（10 s → 2 s 的差别），
     修法是求值器容忍 `=` 并顺带核等式两边；
  2. **`gpt-image-2-token` 是画图模型不是 OCR 模型** → 填了它拍照必失败，
     修法是识别主模型不可用时自动降级到备用模型，并在报错里说清原因。
- **验算覆盖面有限**：只能验"能写成一条四则算式"的题。几何、统计、找规律这类
  题会落到 `unverifiable`，界面显示灰色提示而不是绿勾 —— 这是刻意的，不冒充正确。
- **拍照识别准确率取决于模型**：手写体/模糊照片可能认错，
  所以识别结果**必须可编辑**再讲解（已实现）。
- **聚合站模型可用性会变**：实测 5 个候选模型里 3 个直接 `invalid_model`。
  "模型名在列表里"不等于"能用"，所以识别留了备用模型 `qwen3-vl-plus`。
- **讲解质量取决于模型**：步骤的**正确性**由本地验算兜底，但"讲得通不通俗"本地判断不了。
- **衍生题的判分是文本/数值比对**：单位不写不算错（与练习页一致）。
