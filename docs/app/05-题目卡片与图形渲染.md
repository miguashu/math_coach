# 05 · 题目卡片与图形渲染

> 源码：`app/lib/widgets/question_card.dart`、`app/lib/render/figure_view.dart`、`app/lib/render/vertical_view.dart`

练习页、复习页、错题本页用的是**同一张卡片**，差别只在几个开关。这一篇讲这张卡片，
以及卡片里的图和竖式是怎么画出来的。

---

## 1. 卡片的三种形态

| 形态 | 触发条件 | 表现 |
|---|---|---|
| **作答中** | `correct == null` | 白底灰边，有输入框，无讲解 |
| **批改后** | `correct != null` | 边框绿/红，输入框禁用，展开讲解区 |
| **只读** | `readonly: true` | 无输入框，直接显示「正确答案」，无讲解 |

错题本页用第三种：`RecordCard` 打包 `QuestionCard(q: …, readonly: true)`，
再叠上重要度和错误次数的角标。

## 2. 卡片结构

```
┌────────────────────────────────────┐
│ ┌────────┐                         │
│ │ 第 1 题 │ 数与代数 / 笔算     ✓  │  ← 标签 + 知识点 + 对错图标
│ └────────┘                         │
│                                    │
│ 用竖式算一算：47 + 38 =             │  ← 题干，字号 16，行高 1.5
│                                    │
│          [ 图 / 竖式 ]              │  ← 居中
│                                    │
│ ┌──────────────────────────────┐   │
│ │ 在这里作答                    │   │  ← 输入框（批改后禁用）
│ └──────────────────────────────┘   │
│                                    │
│ ┌──────────────────────────────┐   │
│ │ 💡 思路回顾                   │   │  ← 讲解区（批改后出现）
│ │  正确答案：85                  │   │     答错时才有这行
│ │  1. 个位 7 + 8 = 15，写 5 进 1 │   │
│ │  2. 十位 4 + 3 + 1 = 8        │   │
│ │  3. 结果是 85                 │   │
│ └──────────────────────────────┘   │
└────────────────────────────────────┘
```

**边框颜色即答案**：`correct == null` 灰边（1px）；对绿边、错红边（1.6px）。
不用额外的文字提示"你对了几题"，扫一眼颜色就知道。

## 3. 几何图形怎么画出来的

### 存的不是图，是"语义"

每个几何题在生成时只保存一份 `FigureSpec`：

```dart
FigureSpec(
  type: FigureType.rect,       // 什么图形
  params: {'w': 7.0, 'h': 4.0}, // 多长多宽
  unit: 'cm',                   // 单位
  grade: 3,
  shade: !askArea,              // 要不要涂色
)
```

**没有坐标，没有图片。** 坐标是渲染时才算出来的：

```
FigureSpec（语义）
    ↓  FigureSolver.solve()
FigureScene（坐标 + 图元 + 标注 + facts）
    ↓
  ┌──────────────┬─────────────────┐
FigureView     FigurePdfRenderer   FigureSvgRenderer
（手机屏幕）      （PDF 打印）        （浏览器）
```

三个后端共用同一份 `FigureScene`，所以**同一个图形在三个地方长得一样**。
这也是为什么导出 PDF 时图形不会糊 —— 打印时是重新按 A4 精度算的坐标，
不是把屏幕截图放大。

### FigureSolver 做了什么

```dart
static SolveResult solve(FigureSpec spec) {
  var scene = _dispatch(spec);      // 按图形类型算坐标
  _validate(scene, warnings);       // 退化校验：NaN？空包围盒？自交？
  var withGrid = spec.grid ? _overlayGrid(scene, spec.gridStep) : scene;  // 方格纸
  var finalScene = _avoidLabelOverlap(withGrid);  // 标注避让
  return SolveResult(scene: finalScene, facts: finalScene.facts, warnings: warnings);
}
```

三步：

1. **求解坐标**（`_dispatch`）：按图形类型分派给 `PlanarBuilder` / `SolidBuilder` /
   `LatticeBuilder` / `ChartBuilder`。
2. **退化校验**：出现 NaN/Infinity 直接抛错；多边形面积接近 0 或自交则记 warning。
3. **标注避让**（`_avoidLabelOverlap`）：把挨太近的标注互相推开，
   最多迭代 24 次。这不是锦上添花 —— "标注是否重叠"是明确的验收项。

### 支持的图形

求解器支持 **22 种**图形类型（`FigureType`）：

| 类别 | 类型 |
|---|---|
| 平面基本图形 | 长方形、正方形、直角三角形、一般三角形、平行四边形、梯形 |
| 圆类 | 圆、半圆、扇形、圆环 |
| 组合图形 | 矩形加半圆、正方形内切圆、格点不规则多边形、不规则曲线估面积 |
| 立体与展开 | 正方体展开图、长方体斜二测图、圆柱、圆锥 |
| 统计图表 | 方格纸、条形统计图、折线统计图、扇形统计图 |

### App 里的渲染器

`FigureView` 用 `CustomPainter` 直接画 Canvas，**不引三方 SVG 包**。
原因写在文件头注释里：走 Canvas 少一层依赖，也少一层"拼字符串再解析"的中间环节。

```dart
class FigureView extends StatelessWidget {
  final double pad = 26;   // 给标注文字留的白，固定 px，不随图形尺寸变化
  ...
}
```

> `pad` 固定 px 这个细节是踩过坑的：如果留白按比例缩放，
> 一个半径 3 的圆会被几倍于自身的留白挤成一团。

坐标映射（`tf`）做了一次 y 轴翻转 —— Canvas 是 y 向下，数学是 y 向上：

```dart
Offset tf(Pt p) => Offset(
  (p.x - scene.extent.minX) * scale + pad,
  height - ((p.y - scene.extent.minY) * scale + pad),
);
```

圆弧要额外处理：翻转后起始角必须取 `-(start + sweep)` 才是同一段弧。

### 立体图形的画法规矩（2026-10-18 统一检查后立下的）

立体图形和题面是一体的：**图画错了，题就等于出错了**。三条规矩：

1. **长方体 12 条棱一次画全**（`SolidBuilder.cuboidOblique`）：
   剪影 6 条 + 正面另 2 条 + 顶面右缘 1 条实线，被挡住的 3 条
   （后左竖棱、底面两条）虚线。曾经只画剪影加两条**左/右面的对角线**，
   正面矩形都没闭合 —— 家长复查逮住的就是这个。
   测试断言：每条独立棱的两个端点必须落在 8 个顶点上，不许出现对角线。
2. **展开图判断题必须一半可折、一半不可折**。池子里曾全是可折布局，
   "能不能折成正方体"的答案永远是"能"，孩子无脑答"能"就能全对。
   现在混入 2×3 矩形、两片同侧两个陷阱布局（可折性由
   `CubeNetValidator` 真三维折叠校验把关，不是"看着像"）；求表面积的题
   只用可折布局。讲解按布局生成 —— "中间一排四个"只对一四一型成立。
3. **虚线是语义（被挡住），三个渲染器必须行为一致**（SVG / PDF / Canvas）。
   Canvas 端用 `path.computeMetrics()` 截段画虚线，PDF 端用
   `setLineDashPattern` —— 曾经 App 和打印卷子上隐藏棱全是实线。

图上还要有棱长：展开图在 spec 带 `edge` 参数时于底边标注"棱长"；
老错题重放的 spec 没这个参数，宁可不标也不标错的。

## 4. 竖式怎么保证数位对齐

### 核心做法：每个字符单独定位

`VerticalView` **不把一行数字拼成文本**，而是一个字符一个字符地定位到格子里：

```dart
final cellW = _kFontSize * 1.25;
final cellH = _kFontSize * 1.42;
// 每个字符画在自己格子的中心
final x = ox + c * cellW + cellW / 2;
var y = oy + r * cellH + cellH / 2;
```

**为什么不能拼成文本**：中文字体里的数字通常**不等宽**，
拼成一行文本必然错位。而**数位对齐就是竖式的全部意义** —— 对不齐的竖式还不如不画。

所以这里强制 `fontFamily: 'monospace'`。

### 排版由内核统一产出

`VerticalTypeset.add/sub/mul/div` 产出的不是字符串，而是一个 **`VerticalLayout` 网格**：

```dart
enum VRole { digit, carry, operator, result, remainder, note }

class VerticalLayout {
  final List<List<VCell?>> grid;   // 行 × 列的字符网格
  final Set<int> rulesAfter;       // 哪些行后面要画横线
  final List<String> steps;        // 分步讲解
}
```

好处：

- **位置是数据，不是渲染时的猜测** —— 进位字符在第几行第几列，由排版器算好；
- **屏幕和 PDF 共用同一份网格** —— `VerticalView`（Canvas）和
  `VerticalPdf`（PDF）画的位完全一样；
- **讲解和算式同源** —— `steps` 和 `grid` 是同一次计算产出的，不会对不上。

### 进位小字

进位数字（比如加法里进上去的「1」）特殊处理：

```dart
final isCarry = cell.role == VRole.carry;
if (isCarry) y -= cellH * 0.28;              // 往上抬一点，落在两行之间
final size = isCarry ? _kFontSize * 0.58 : _kFontSize;
final color = isCarry ? const Color(0xFFDC2626) : const Color(0xFF1E293B);
```

字号 58%、位置抬高 28%、红色 —— 这是课本上竖式的标准视觉约定：
进位是"辅助记号"，不能跟正式数字混在一起看。

### 长除法（「厂」形）

`LongDivisionView` 画的是中国教材的标准形式：

```
        8
      ┌──────
    7 │ 5 8
        5 6
        ───
          2
```

- 商写在横线上方；
- 「厂」形：一条横线覆盖整个被除数，左竖向下；
- 除数在左侧，被除数在厂内；
- 逐步展示：乘积 → 相减横线 → 余数；
- 不能整除时，右侧追加 `……余数`。

## 5. 容错

卡片里所有"从 spec 重放"的地方都包了 `try/catch`：

```dart
Widget? _figureWidget(BuildContext context) {
  try {
    s = FigureSolver.solve(FigureSpec.fromJson(spec)).scene;
  } catch (_) {
    s = null;   // 求解失败就返回 null，卡片退化成"无配图"
  }
  ...
}
```

**设计原则**：一道题的图画不出来，不应该让整页崩掉。
宁可显示一道没有配图的题（题干还在，还能做），也不要白屏。

## 6. 已知边界

| 边界 | 说明 |
|---|---|
| 图宽自适应 | `(屏宽 − 68).clamp(120, 340)`，小屏上图形会偏小 |
| 竖式字号固定 20px | 不随系统字体缩放 |
| 长除宽度固定 210px | 被除数很长时可能超出 |
| 图形求解失败静默 | 只退化成无图，不给用户提示 |
| 标注避让是迭代近似 | 极端情况下仍可能重叠（迭代上限 24 次） |
| 不支持动画 / 分步演示 | 静态图，不能"一步一步展示计算过程" |
| 老错题的展开图无棱长标注 | spec 没存 edge 参数，无法恢复题面棱长，宁可不标 |
| 圆柱/圆锥仍是"够用"画法 | 圆柱下底整圆虚线（不做半弧遮挡）、圆锥轮廓线是解析切线 —— 形准但不是美术级 |
