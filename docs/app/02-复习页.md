## 1. 这一页和「错题本」有什么区别

这是最容易混的两个页面，先说清楚分工：

| | 复习页 | 错题本页 |
|---|---|---|
| 回答的问题 | **什么时候该再见一面** | **哪几题最该盯** |
| 排序依据 | 到期时间先后（重要度优先） | 重要度高低 |
| 数据来源 | `repo.dueQueue()` —— 只挑 `due ≤ now` 的 | `repo.all` —— 全部记录 |
| 会不会空 | 会，而且是**正常的** | 只有没做过题时才空 |
| 交互 | 可作答、可批改 | 只读，只能移除 |

**一句话**：错题本是「库存清单」，复习页是「今天的待办」。

## 2. 界面结构

```
┌────────────────────────────────┐
│  复习              ┌─────────┐ │
│  到期的题会在这里出现 │ 6 道待复习│ │  ← 角标数字
└────────────────────────────────┘
┌────────────────────────────────┐
│  ┌──────────────────────────┐  │
│  │ ✓ 答对 5 / 6             │  │  ← 提交后出现（绿/蓝底）
│  │   全对，间隔会自动往后推   │  │
│  └──────────────────────────┘  │
│                                │
│  ┌──────────────────────────┐  │
│  │ 复习 1    数与代数 / …    │  │
│  │ 用竖式算一算：58 ÷ 7 =    │  │
│  │      [ 长除法图 ]         │  │
│  │  ┌────────────────────┐  │  │
│  │  │ 在这里作答          │  │  │
│  │  └────────────────────┘  │  │
│  │ ┌────┐ ┌────┐ ┌────┐     │  │  ← 批改后：答对才有
│  │ │有点难│ │会了 │ │很简单│     │  │
│  │ │2天后│ │5天后│ │12天后│     │  │
│  │ └────┘ └────┘ └────┘     │  │
│  └──────────────────────────┘  │
│            …                   │
└────────────────────────────────┘
│  [  提交批改 → 确认归档 → 下一轮 ] │  ← 底部按钮三态
└────────────────────────────────┘
```

**自评那一排的三个数字**（`2天后 / 5天后 / 12天后`）不是写死的，是
`FsrsScheduler.previewIntervals()` 对这道题**当场算**出来的。
没有它，孩子点「有点难」和「很简单」是盲选 —— 反正也不知道自己在选什么。

**底部按钮三态**：

| 状态 | 文案 | 点下去 |
|---|---|---|
| 未批改 | 提交批改 | 只判对错，**不落账** |
| 已批改 | 确认归档 | 带上自评一起写进 FSRS |
| 已归档 | 下一轮 | 清空输入，回到未批改 |

**底部导航的角标**：复习 Tab 上会显示到期题数（红点数字），不点进去也知道有东西要做。
这个数字来自 `s.dueQueue().length`，在 `_Shell` 里每次重建都会重算。

## 3. 复习队列是怎么排的

```dart
List<ReviewRecord> dueQueue(DateTime now, {int limit = 20}) {
  final list = _records.values.where((r) => r.isDue(now)).toList();
  list.sort((a, b) {
    final c = b.importance.compareTo(a.importance);   // 先比重要度（降序）
    return c != 0 ? c : a.fsrs.due.compareTo(b.fsrs.due);  // 同重要度比到期时间
  });
  return list.take(limit).toList();
}
```

排序规则：**重要度降序 → 到期时间升序**。
意思是「又重要又拖了很久的排最前」，一次最多取 20 道。

`isDue(now)` 的定义：`!fsrs.due.isAfter(now)`，即 `due ≤ now`。

## 4. 点下去发生什么

现在是**两阶段**：先批改（不落账）→ 自评 → 再归档。

### 阶段一：提交批改（不落账）

```dart
void _grade(List<ReviewRecord> rs) {
  // 本地判对错、数正确数，答对的题预置自评为 good
  setState(() { _graded = true; _archived = false; _correct = c; });
}
```

**为什么不先落账再改**：FSRS 的评分是进算法算 stability 的。
已经算过一次再"补一次修正"，会把 `reps` 记成两次、间隔也算歪 ——
宁可多一次点击，也不能让"自评"变成事后打折。

没点「确认归档」就离开 = 这次没练。题目还在队列里，不会被记成错题，
也不会污染间隔。这比"悄悄记一笔错的"安全得多。

### 阶段二：自评（只给答对的题）

```dart
if (_graded && verdict == true && !_archived)
  _SelfRateRow(
    record: r,
    value: _self[r.id] ?? Rating.good,
    onChanged: (v) => setState(() => _self[r.id] = v),
  ),
```

- **答对的题**：三档「有点难 / 会了 / 很简单」，每档下面标着多久后再见
- **答错的题**：不给选，直接写「没做对 → 一会儿就再来一次」
  —— 错就是错，没有"错得有点难"这一说

### 阶段三：确认归档

```dart
await widget.state.submitReview(rs, answers, selfRatings: _self);
```

最终记哪一档由**全项目唯一的入口** `ratingFor()` 决定：

```dart
Rating ratingFor({required bool correct, Rating? selfRated}) {
  if (!correct) return Rating.again;            // 答错只能是 again
  if (selfRated == null || !selfRated.isPass) return Rating.good;
  return selfRated;                             // 答对用自评
}
```

> 以前每个调用点各写一遍 `correct ? Rating.good : Rating.again`，
> 结果 `hard` / `easy` 从来没人传 —— 四级评分里两档是死的。现在统一走这里。

`submitReview` 里有一个**和练习页不同的处理**：

```dart
// 留空不算答对，也不算答错 —— 只是这次没做，不能污染间隔
if (input.isEmpty) continue;
```

练习页里留空算错，复习页里留空**跳过**。差别的原因：

- 练习是「给反馈」，空着也是"这题没答上来"，给个错合理；
- 复习是「调间隔」，空着不代表忘了，只是这次没点它。
  如果按错处理，孩子随手划过几道题，间隔就被拉回原点，整个调度就废了。

### 答错之后

`Rating.again` 走 FSRS-6 的**遗忘分支**（`nextForgetStability`）：

```dart
longTerm  = w11 * D^(-w12) * ((S+1)^w13 - 1) * e^((1-R) * w14)
shortTerm = S / e^(w17 * w18)
newS      = min(longTerm, shortTerm)      // 官方就是取较小者
due       = now.add(config.lapseStep)     // lapseStep = Duration.zero
```

里面 `D^(-w12)` 这一项是自研简化版完全没有的：**难的内容忘得更快、重建更慢**。

**`lapseStep = Duration.zero` 是这个设计的关键**：答错后 `due = now`，
也就是说**立刻重新到期**。孩子提交后点「下一轮」，答错的题马上又出现在队列里。

为什么不按算出来的稳定间隔推到三天后：错题必须趁热重练一次，
等三天后再见，这段讲解早就忘干净了 —— 那样错题本就失去意义了。

### 下一轮

清空所有输入，回到未批改状态。此时队列会重新计算 —— **答对的题已经把 due 推后了，
会从队列里消失**；答错的题 due 还是 now，会再出现一次。

所以「下一轮」的实际效果是：**只重做错的那几道，直到连续答对为止。**

## 5. 空状态文案

复习页空了不代表"没有错题"，文案专门澄清了这点：

> 暂时没有要复习的
> 不是"没有错题"，而是都还没到该再见的时刻。
> 等间隔到了会自动回来。

如果这里只写"暂无内容"，家长会以为数据丢了。

## 6. 已知边界

| 边界 | 说明 |
|---|---|
| 一次最多 20 道 | `dueQueue(limit: 20)`，更多要分几轮 |
| 页面级 `_graded` | 批改状态存在页面 State 里，**切走再切回会重置**（数据不丢，只是要重新提交） |
| 留空跳过 | 空答案不影响间隔，但也不会有反馈 |
| 自评只在复习页 | 练习页 / 拍照判卷 / 闯关都走 `ratingFor(correct: ...)` 的默认值（答对 good、答错 again），没有自评入口 —— 那些场景一次作答就走完了，再让孩子评一次是负担 |
| 没归档就切走 = 这次没练 | 批改状态在页面 State 里，切走会重置；题目还在队列，不会记错账 |
| 队列实时重算 | 每次 `build` 都调 `dueQueue()`，记录多了（`_records` 遍历）会有轻微开销，当前规模可忽略 |

## 7. 四档评分各用过几次（家长视角）

每条记录上有一个 `ratingCounts`：

```dart
'ratingCounts': {'1': 2, '2': 6, '3': 12, '4': 5}
//                again  hard  good  easy
```

看「错了 3 次」只知道结果；看「5 次很简单 / 12 次会了 / 6 次有点难」
才知道孩子是真会还是硬撑。**这是四级评分唯一的对外出口** ——
只在算法里打转、界面上看不见，等于没做。

老备份没有这个字段，`fromMap` 读成空 Map，不炸。

## 8. 那些 FSRS 数字是怎么来的（不许手算）

`test/fsrs6_test.dart` 里几百个期望值**一个都不是手算的**，全部由官方实现算出来：

```bash
pip install fsrs
python tool/gen_fsrs_refs.py
```

脚本做的事：调 `py-fsrs`（FSRS-6 官方 Python 实现）的 `_next_stability` /
`_next_difficulty` / `_initial_stability` / `_initial_difficulty` / `_next_interval`
导出参考值 → 写 `app/build/fsrs_refs.json` → 生成 `test/fsrs6_test.dart` 的**数值段**，
行为段取自模板 `tool/fsrs_test_tail.dart.txt`（原样保留）。

两个踩过的坑，别再踩：

1. **参考值必须写完整精度**。曾经用 `round(v, 6)` 省字符，结果和 Dart 差 3e-7，
   比 1e-9 的容差还大，4 条断言凭空变红。
2. **断言增速，不要断言 stability 的绝对值**。真 FSRS-6 的 stability 会一直涨
   （记得越牢本来就该间隔越久），40 次 easy 后能到 2.46e10。
   该收敛的是**每次的增长倍率**（n=12 时 1.89，n=60 时 1.12），不是 S 本身。
