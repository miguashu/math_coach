## 二、点下去发生什么

### 1. 拍照识题（视觉模型 + OCR 提示词）

1. 调系统相机拍照或从相册选图（**没申请相机权限**，走 `ACTION_IMAGE_CAPTURE` / `ACTION_GET_CONTENT`）；
2. 缩到 1024 px、由 **Android 宿主编成 JPEG q72**（`dart:ui` 只能编 PNG，而 PNG 对照片几乎是灾难）、base64；
3. 发给识别模型，提示词只让它做一件事：**把这张图上的所有题目原文抄出来（≤8 道），不许解题、不许给答案**；
4. 认出来几道题就出几**张卡**，一题一卡，每张卡各有「一步一步讲」「出同类题」两个按钮；
   题干填进可编辑输入框 —— **必须家长/孩子确认后才进讲解**，不拿识别结果直接当真理；
5. 主模型报"这个模型走不了对话接口"时，自动换备用模型 `qwen3-vl-plus` 再试一次。

> **为什么要改成一图多题**（2026-10-17 家长反馈）：原来提示词只要求"抄出这一张上的题目"，
> 模型就只回一道 —— 于是一张 5 题的卷子要拍 5 次。改成明确要求返回 `{"items":[…]}` 后，
> 真机实测一张 5 题卷 → 「认出来 5 道题」逐题分卡，11.1 s（3167 tokens）。
> `OcrResult.stem` 仍然保留（取第一道），老调用方不破。
>
> **为什么非要 JPEG**：`lib/ai/llm.dart` 里 data URL 写的本来就是 `data:image/jpeg`，
> 也就是"声明 JPEG、实际发 PNG" —— 一部分服务端会拒收或走兜底解码。
> 改成真 JPEG 是**又小又更对**，不是单纯省流量。实测一张 1024px 拍照风格图：
> PNG 1935 KB vs JPEG q72 265 KB（**7.3 倍**）；纯白底印刷体只有 2.3 倍。

### 2. 分步讲解 Agent

不是"问一次模型就完事"，而是一个**会打回重做的循环**：

```
第 1 次调用 → 模型按 JSON 输出 {steps[], answer, unit, equation}
   ↓
① 完整性检查：少于 2 步 / 没说答案 / 答案读不出数字 → 打回
② 本地验算：equation 用 Rational 精确重算，和 answer 对不上 → 打回
   ↓（携带失败原因再发一次）
第 2 次调用 → 仍不符就如实标红，不冒充正确
```

验算结果**三态**，不许二态：

| 状态 | 界面显示 | 含义 |
|---|---|---|
| `exact` | ✅ 已本地验算 | 本地精确复算与模型答案一致 |
| `unverifiable` | ⚠ 未能本地验算 | 题目写不成一条算式（应用题常见）—— 不亮绿勾 |
| `mismatch` | ❌ 验算不一致 | 算出来和模型报的不是一回事 |

### 3. 同类题 / 衍生题

- **简单题（能识别成一条纯四则式，如 `377-98=`）→ 本地生成**：改数字、答案用 `Rational` 精确算，
  不联网、不可能错；
- **应用题 → 模型生成**：模型出完还要**自己再解一遍**，本地再拿它的验算式复算一次，
  两边不符就**丢掉这道题**（宁可少出一道，也不出答案错的题）。

两者共用一份题型→模板映射（`lib/variant/mapping.dart`），但**尺度刻意不同**：

| | 用在哪 | 判据 | 映射不上时 |
|---|---|---|---|
| `localRecipeFor`（严格，题型 + 算法结构） | 判卷后自动衍生题 | 结构判不出来就返回 null | 交给模型按原题干出 |
| `variantKindFor`（宽松，只看题型名） | 错题本「变体闯关」按钮 | 认得出题型就行 | 由 `fallbackVariantKind` 按年级兜底 |
| `fallbackVariantKind`（年级兜底） | 同上，最后兜底 | 不看原题 | 出同年级常规题，保证按钮点了有反应 |

为什么衍生题必须比变体闯关严：衍生题挂在**一道具体的错题**下面，
家长看到的是「这道题不会 → 给你几道同类的」，**出成另一个算法就是骗人**；
而「变体闯关」是家长主动点的按钮，点下去必须有反应，
出个同年级的常规题是可以接受的（它连原题型都不要求）。

### 4. 整卷 AI 出题（练习页「提高 / 奥数挑战」档）

`lib/ai/quizgen.dart`，家长原话驱动的功能："大模型出新，系统补全"。

- **模型负责出新**：按年级 + 知识点 + 难度档出完整应用题，要求 2~4 步讲解，
  并给一条从条件到答案的 `equation`；
- **系统负责补全与把关**：
  - 答案 = 本地 `Rational` 从 equation 复算的值（**不是模型报的数字**）；
  - 模型自报答案与复算不符 → 整道丢弃（它连自己都不认同）；
  - 没有 equation / 步骤 <2 / 题干含"如图/下表" / 答案非有限小数 → 丢弃；
  - 知识点由本地 `KnowledgeIndex` 重新归类（年级优先），难度按档位夹紧；
  - 按每次 ≤3 道分批问模型（一次要 6~10 道会超时、烧光 token 预算）；
  - 混卷：AI 题在前、本地题补足、题干归一化去重、绝不为空；
  - 最近 40 条题干落盘，出题时作为避重清单传给模型。
- **三档难度**：基础（纯本地，零网络请求）/ 提高（一半 AI）/ 奥数挑战（AI 为主，≤6 道）。

**本地没收录这个单元时，先不出题**（2026-10-17 家长反馈"点出题秒出 6 道，
可既不是 AI 出的也不是这个单元的"）：原来这种情况下本地题是**立刻**上屏的，
而那几道题根本不是所选单元。现在 `wantAi > 0` 且 `covers()` 为假时
`current` 先给空数组，界面明写「『$unit』本地题库还没收录，正在用 AI 按这个单元出题…」；
AI 也没出成才回落本地，并且明确说明"这些不是所选单元的题"。
**拿不相干的题充数比不出题更糟** —— 孩子会以为自己练了那个单元。

### 5. AI 判卷（练习页「拍照判卷」，`lib/ai/grader.dart`）

家长原话："我需要有个判卷子的 AI Agent，出的题能根据照片进行判断。"
典型用法：这一套题导出 PDF 打印出来给孩子做，写完拍一张照片回来批。

**三步分离，每步只干一件事**：

| 步骤 | 谁干 | 干什么 | 干错了会怎样 |
|---|---|---|---|
| ① 认字 | 模型（vision，temperature 0.1） | 把手写答案读成文本。原样抄出（`7……5` 不许约成 `7.5`）；认不出留空 + note 注明，**不许猜**；不抄印刷体题干 | 认错字 → 被第 ② 步逮住；确认前用户还能改 |
| ② 判分 | **本地** `QuizAnswer.check` | 规范化比较：全角半角、单位剥离、小数尾零、余数写法、数值容差。逐字实时重判 | 与模型解耦，模型怎么认都不影响判定权威 |
| ③ 批语 | 模型（chat，temperature 0.4） | 只给本地判为错的题写一两句批语：先说错因（算式错/概念混/漏步骤/抄错数），再鼓励；**不提正确答案** | 失败只丢批语，判卷结果照常落账 |

**为什么判分不能交给模型**：模型既认字又判分的话，它认错字就会顺手判错 ——
把 `79` 认成 `96`、把 `7……5` 认成 `7.5`，孩子白背一个错题。
所以判定权威必须在本地，模型只负责"纸上写了什么"和"错在哪"。

**认不出不判错**：空答案或字迹不清（note 非空）一律 `unclear`，
标「未识别」—— 没看清就判错是冤枉孩子。未识别的题不进错题本，
练习页显示琥珀色卡片，家长可照着照片手动补判。

**提示词防泄题**：认字阶段的 prompt 只含题干，**不含正确答案**
（JSON 示例也用占位符，不用真实数字，防模型照着填）。

**兜底**：主识别模型报 `modelMissing` 时自动换备用模型（同 `ocr.dart` 套路）；
认卷失败给明确原因（"可能是拍摄不清晰"），不黑屏。

### 6. 错题衍生题（判卷之后自动进题库，`lib/ai/derive.dart`）

家长原话："判卷结束后，把错题引入错题本，同时生成衍生题。衍生题进题库。"

判卷确认之后，**每一道判错的题**都会造 3 道同类题存进「衍生题库」
（错题本页的第二段，见 `03-错题本页.md`）。两条路：

| 路 | 什么时候走 | 答案怎么保证 |
|---|---|---|
| ① 本地变体模板 | 错题的题型能严格映射到一个模板，**且算法结构判得出来**（加法/减法、乘法、倍的认识、有余数除法、长方形面积或周长、三角形、圆面积、单位换算、购物找零） | `VariantGenerator` 按结构改数字 + `Rational` 精确算，**不联网**，不可能错 |
| ② 模型按原题干出 | 本地没有同算法模板的题型（混合运算、植树/间隔、平均数、梯形、平行四边形、圆周长、组合图形、格点图形、立体图形与展开图、求一个数的几分之几、AI 现场出的应用题） | 模型必须给出 `equation`，本地 `ExprEval` + `Rational` 复算**必须一致**，否则整道丢弃 |

**判据只有一条：孩子做这道衍生题时，用的算法和原题一样吗？**

这个名字听起来相关不算。本地这条路上光看**题型名**还不够 ——
一个题型里往往藏着几种算法，所以衍生处方里要带**结构**（`VariantShape`）：

| 题型 | 藏着的结构 | 只按题型名映射会出的错 |
|---|---|---|
| `rect` | 面积 `长×宽` / 周长 `(长+宽)×2` | 面积错题衍生出**周长**题 |
| `timesAs` | 求几倍（一步乘）/ 一共多少（先乘后加） | 两步题衍生出**一步**题，漏掉最后一步 |
| `sub` / `add` | 减法 / 加法 | 减法错题衍生出**加法**题 |
| `shopping` | 找零（先乘后减） | 两步题衍生出**一步**求总价 |
| `fractionOf` | 求一个数的几分之几 = `÷分母×分子` | 映射到"同分母分数加减"，**完全另一个算法** |

**这不是理论风险，是真机上跑出来的**（2026-10-17，模拟器判卷 → 衍生 → 题库）：
12 道衍生题**全部** `origin=local`，其中

- 长方形**面积** 8×5 的错题 → 衍生成「长 12 宽 4，它的**周长**是多少？」（3 道里错了 2 道）
- 不退位**减** `731 − 463` 的错题 → 衍生成「**573 + 652** = ？」（加号）
- **倍的认识**（`3 + 3×2`，两步）→ 衍生成「每盒 38 支彩笔，买 3 盒」（一步乘）
- **简单购物**（`60 − 6×4`，两步找零）→ 衍生成「一支 28 元，买 11 支要花多少元」（一步乘）

四道题**答案本身都没算错**，所以原来那套闸门（只验"答案对不对"）一道也拦不住。
但孩子练的是**另一个考点**，连对两次会在题库里留下假的「已掌握」——
比不出题更糟。所以现在的做法是：

1. 结构由处方的 `shape` 显式带来（`localRecipeFor`），模板**照结构出**，
   闸门里还多一道"结构是命令不是建议"的检查（要求减法出了加法 → 整道丢弃）；
2. **判不出结构就返回 null**，退到模型那条路，绝不在本地硬凑一道；
3. 结构从题干读（本地题库的题干是模板生成的，每种结构问法固定），
   读不出结构说明这不是本地出的题 —— 保守但不会错。

回归靠 `test/derive_shape_manual.dart`：它拿**真实出题器产出的 1560 道题干**
当输入，逐道派生并以**独立于生成器的公式**复算答案（`test/derive_shape_manual.dart`
里的 `_expectByShape`），当前 79 条断言、2703 道衍生题全部同结构同答案。
为什么不手写题干：手写只能证明"我想到的情况对了"，真实题干才能证明"线上出的题都对"。

**为什么第 ② 路比「同类题」功能更严**：题库是**持久**的。
错题本里错一次只是丢一条记录；题库里躺一道错答案，孩子每次练都在巩固一个错误。
所以这一路五道关，缺一不可：

1. 题干不许出现"如图/下图/统计表/数轴"—— 纸面上没有图，孩子看不懂；
2. 必须给出验算式（没给 → 丢弃，不给"模型自己解过一遍"的信任额度）；
3. 验算式必须能被 `ExprEval` 解析；
4. 本地复算结果必须与模型自报答案一致；
5. 答案必须是有限小数（不出循环小数）。

**本地优先是性能设计**：本地模板是毫秒级、零 token，所以**有模板的题根本不进 prompt**
（省 token 也省时间）。只有没模板的错题才会攒成**一次**请求批量问模型
（最多 6 道原题 → 一次调用），不是一道一次。

**出不来就说清楚，不假装成功**：没配 key、模型没给出能过闸门的题、
一次判卷里错题太多（超 6 道）—— 这些都会写进 `skipped`，
通过 `AppState.deriveNote` 显示成一句人话（"到「设置 → AI」配好 key 就能让模型按原题出"）。

**后台跑，不挡判卷**：判卷结果是家长等着看的东西，衍生题是加分项。
所以 `deriveFromWrong()` 是 `unawaited` 出去的，判卷该多快还多快，
状态条（`_DeriveStatus`，用 `ListenableBuilder` 单独监听 AppState）自己刷新进度与结果。

## 三、背后靠什么算出来（铁律）

1. **模型只输出数学关系，不输出坐标** —— 几何图形坐标一律本地求解器算，模型说了也不采纳。
2. **答案本地算** —— 讲解的 `equation`、同类题的答案，全部过 `ExprEval` + `Rational` 精确有理数复算。
   `Rational` 是分数实现，`1/3` 不会被当成 `0.3333`。
3. **不联网也能用** —— 出题、判分、复习、导出 PDF 全在本地。AI 只增强"拍照"和"讲解"两块，
   key 失效、断网，App 其余功能不受影响。

## 四、真机实测（2026-10-16，本机真实联网）

之前这一块只有假模型（`FakeLlm`）跑过逻辑，**真链路没验过**。这次拿真实 key 打了一遍，
脚本留在 `test/live_agicto.dart`（手动跑：`dart run test/live_agicto.dart`）。

### ① 三个模型候选，只有一个能识题

| 模型 | `/chat/completions` | 结论 |
|---|---|---|
| `deepseek-v4-flash` | ✅ 200，两张测试图 OCR 全对 | **默认用它，文字与识图一家搞定** |
| `qwen3-vl-plus` | ✅ 200，OCR 全对 | 备用识别模型 |
| `gpt-image-2-token` | ❌ 500 `invalid_model` | **是图像生成模型**，走 `/images/generations` 才通（实测能出图），不能识题 |
| `gemini-2.5-flash-image-preview` | ❌ 500 `invalid_model` | 该中转站上不可用 |
| `qwen3-vl-8b-instruct` | ❌ 500 `Model not exist.` | 该中转站上不可用 |

> **`gpt-image-2-token` 不能当识别模型用。** 它出现在模型列表里，但只在画图接口上有效。
> 填了它拍照会失败 —— 现在的处理是：报错里直接告诉用户"这多半是画图模型，换 `qwen3-vl-plus` 试试"，
> 并且识图时会自动降级到备用模型再试一次，而不是让用户对着一条 HTTP 500 发呆。

### ② 讲解三道，全部一次通过

| 题 | 年级 | 步数 | 答案 | 验算 | 耗时 |
|---|---|---|---|---|---|
| `237 + 158 = ?` | 2 | 3 步 | 395 | 已本地验算 | 6.5 s |
| 绳子 12 米用去 3 米又 4 米 | 3 | 3 步 | 5 米 | 已本地验算 | 2.1 s |
| 长方形 9×6 面积 | 5 | 2 步 | 54 平方厘米 | 已本地验算 | 2.8 s |

讲解示例（第 1 题，模型原话）：

> 第一步：把数位对齐 —— 把 237 和 158 上下写，个位对个位、十位对十位，就像排队要站整齐。
> 第二步：先算个位 —— 7 加 8 等于 15，个位写 5，向十位进 1。就像个位太挤了，送 1 个到十位。
> 第三步：再算十位和百位 —— 3 加 5 再加进上来的 1 等于 9；百位 2 加 1 等于 3。

### ③ 拍照 → 讲解 端到端

测试图（`tool/testdata/probe.png`，白底黑字两行题）识别结果：

```

备注：下方另有一道文字题（小明有12个苹果…），非主要题目，未提取。

```

接着拿识别出的题干直接讲解：3 步、答案 395、已本地验算、3.8 s。

### ④ AI 判卷端到端（合成手写答卷）

没有真实手写答卷照片，就用 Python 合成一张：题干用黑体印（像打印的练习卷），
答案用 Ink Free 手写体、逐字随机旋转 ±7° 抖动（`tool/make_grade_sample.py`）。
卷子 5 题：3 题写对（含刁钻的余数写法 `7……5`）、1 题**故意写错**（`90`，应为 100）、
1 题空着不写。探针：`dart run tool/grader_probe.dart tool/testdata/grade_sample.jpg`。

实测输出（deepseek-v4-flash，认卷 2.6 s / 1.3k tokens）：

```
第 1 题：认出 "79"    → 本地判对（正确答案 79）
第 2 题：认出 "7……5"  → 本地判对（正确答案 7……5）   ← 余数写法没被抹掉
第 3 题：认出 "0.25"  → 本地判对（正确答案 0.25）
第 4 题：认出 "90"    → 本地判错（正确答案 100）      ← 手写错字被本地逮住
第 5 题：未识别（未作答）→ 不判错

── AI 批语 ──
第 4 题：这道乘法题算错了，可能是口诀或进位没算准，结果就差了一点。
         别急，下次把进位记牢，你会算得又快又准！
```

第一版合成图第 4 题抖动过大（±7°），模型自己标了"字迹潦草，形似 90，
也可能是 100，无法确定"→ 按设计走「未识别」不判错。
把该题抖动降到 ±2° 后稳定认出 —— 这恰好证明了**设计的安全方向**：
拿不准时不猜，而不是瞎判。

> **合成图的局限**：Ink Free 是规整的手写体，真实儿童字迹更飘。
> 认不出率的真实水平要等家长真机使用后才能统计；但"认不出 → 未识别 → 不判错"
> 的退化路径是安全的，这一点已经被这次实测验证。

## 五、实测暴露并修掉的两个真缺陷

### 缺陷 1：模型写验算式带等号（首次实测）

**现象**：第一版实测三道题，日志里**每一道都是"尝试 2 次"** —— 说明第一次全被打回。

**根因**：把模型第一次的原始返回打出来看（`tool/solver_probe.py`），它把验算式写成了

```json
"equation": "237 + 158 = 395"
"equation": "12 - 3 - 4 = 5"
```

**带等号**。而当时的求值器遇到 `=` 直接判"不是纯算式"→ null → 判 `mismatch` → 打回重做。
模型写算式顺手带答案是人的习惯，靠提示词根本拦不住。

**修法（两处，双保险）**：

1. `ExprEval` 容忍等号：取等号左边求值，右边若是数字还顺带核一遍 ——
   左右不相等说明这道算式自相矛盾，返回 null（判 `mismatch`，比原来更严格了）；
   等号多于一个或左边为空则不猜，直接放弃验算。顺手补了全角 `－` `＝` `＋` 的归一化。
2. 提示词里明确写"只写算式本身，不要写等号和答案"。

**效果**（同一套题重跑）：

| | 修之前 | 修之后 |
|---|---|---|
| 尝试次数 | 每题 2 次 | 每题 **1 次** |
| 耗时 | 5.3 s / 9.9 s / 10.1 s | 6.5 s / **2.1 s** / **2.8 s** |
| tokens | 1626 / 2330 / 2103 | 1261 / **525** / **639** |

第 2、3 题快了 5 倍、省了 3~4 倍 token。

### 缺陷 2：推理模型的 token 预算被思维链吃光（真机反馈）

**现象**：家长在 App 的「AI 设置」里点「测试连接」，**解题模型和识别模型两项同时报失败**。

**排查**：拿真实 key 逐层复现 —— key 有效（能拉模型列表）、模型能用、
识图也正常（`tool/vision_probe.py` 两个模型都正确读出题干）。
那么问题只可能在**请求参数**上。

**根因**：`deepseek-v4-flash` 是**推理模型**，会先输出一段思维链
（`reasoning_content`），再给正式回复。而「测试连接」当初为了省 token 写死了
`maxTokens: 16` —— 16 个 token 全被思维链吃掉，正式回复一个字都没写出来：

```json
{
  "finish_reason": "length",
  "message": { "content": "", "reasoning_content": "We need answer Chinese..." },
  "usage": { "completion_tokens": 16 }
}
```

`content` 是空字符串 → 客户端判「模型返回了空内容」→ 报失败。
**两处测试都写了 16，所以两项一起挂** —— 这正是家长看到的现象。

**修法（三层，逐层兜底）**：

1. **测试连接给足预算**：`16 → 512`。测试要的只是"能不能回话"，
   但推理模型得先想完才开口。
2. **客户端自动补发**（`lib/ai/llm.dart`）：拿到 `finish_reason=length`、
   `content` 为空、`reasoning_content` 非空时，**自动把预算放大 4 倍重试一次**
   （上限 4000）。这样所有调用点都不用各自操心这件事。
3. **错误信息说清病因**：万一放大到上限仍不够，就明说"思考过程用完了 token 预算"，
   并提示换非推理模型 —— 而不是丢一句含糊的「返回了空内容」让家长猜。

**顺带放宽的预算**：`max_tokens` 是**上限、不是预扣**（用不到不扣费），
所以识题 1200→2000、讲解 1800→3000、出题 1800→3000，给思维链留足空间。

**回归**：`test/live_agicto.dart` 新增第 ④ 项 —— 直接拿 `maxTokens: 16`
打一次，验证能自愈：

```
【④ 推理模型的 token 预算自愈】
   只给 16 tokens 也拿到了回复："正常"（共 82 tokens）
  ✅ 预算被思维链吃光时自动补发
```

实测 15/15 通过，离线回归 57/57 通过。

## 七、已知边界（如实列）

| 边界 | 说明 |
|---|---|
| 默认 key 写在代码里 | 预置的 key 明文在 `lib/ai/config.dart` 的 `fallback` 里，为的是"装完就能用"。**这个 key 已经在对话里明文出现过，建议换新 key 后在设置页覆盖**；App 不会把 key 上传，只存本机私有目录 |
| `deepseek-v4-flash` 能识图是中转站的行为 | DeepSeek 官方模型本身不支持图片输入，这个中转站接受了图片并 OCR 成功。哪天中转站改路由，识图会失败 —— 所以留了备用模型自动降级 |
| 聚合站模型可用性会变 | 实测 5 个模型里 3 个直接 `invalid_model`。模型名在列表里 ≠ 能用 |
| 复杂几何图形的拍照 | 目前只要求模型"用一行说明形状与已知条件"，坐标仍由本地求解器算；拍照里的几何图不会自动转成可交互图形 |
| 讲解仍在模型侧 | 步骤的**正确性**靠本地验算兜底，但"讲得好不好"取决于模型，本地判断不了 |
| 无离线兜底讲解 | 断网时拍照页不可用（其余功能不受影响） |
| 衍生题有配额 | 一次判卷最多为 6 道错题问模型（本地模板那一路不限额）；超出的下次自动补 |
| 衍生题看的是"模型能不能给验算式" | 应用题里有些情境（如"够不够""哪种方案省"）天然写不出一条四则式，这类题会被闸门丢掉 → 少几道是正常的 |
| 没配 key 时只有本地模板那一路 | 立体图形、展开图、AI 现场出的应用题都造不出衍生题，界面会如实说明原因 |
